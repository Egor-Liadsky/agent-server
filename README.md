# agent-sever

HTTP-сервис `agentd`: принимает промпт по HTTP, прогоняет его через явный
конвейер обработки (нормализация → входные политики → вызов модели →
выходные политики → судья) и возвращает нормализованный ответ. Ключ
провайдера принадлежит сервису и никогда не приходит от клиента.

Ядро (вызов модели, настройки диалога, телеметрия, конвейер) живёт в
библиотеке `agentcore` из репозитория
[agent-cli](https://github.com/Egor-Liadsky/agent-cli) и подключается
git-зависимостью. Оттуда же подключается `agentupstream` — крейт с обращением
к облачному провайдеру. Он вынесен из ядра намеренно: консольный клиент
`agentcli` от него не зависит, поэтому ходить в облако напрямую он не может, а
делает это только через `POST /v1/chat` этого сервиса. Локальный Ollama —
исключение: клиент вызывает его сам, минуя сервис.

Провайдера выбирает сам сервис по полю `settings.provider` запроса:
`cloud` — `agentupstream`, `ollama` — локальный агент из `agentcore`.

## Конфигурация

Конфигурация читается только из переменных окружения. Пользовательский
конфиг консольного клиента (`~/.config/agentcli/config.toml`) сервис
не читает.

| Переменная                   | По умолчанию              | Назначение |
|------------------------------|---------------------------|------------|
| `AGENTD_UPSTREAM_API_KEY`    | —, обязательна            | Ключ провайдера модели. Без него сервис не стартует |
| `AGENTD_LISTEN_ADDR`         | `0.0.0.0:8080`            | Адрес прослушивания целиком |
| `PORT`                       | —                         | Порт, если `AGENTD_LISTEN_ADDR` не задан (хостинги задают его сами) |
| `AGENTD_UPSTREAM_BASE_URL`   | `https://api.deepseek.com`| Базовый адрес OpenAI-совместимого API |
| `AGENTD_MODEL`               | `deepseek-chat`           | Модель по умолчанию |
| `AGENTD_ALLOWED_MODELS`      | пусто                     | Список моделей через запятую. Пусто — разрешена только `AGENTD_MODEL` |
| `AGENTD_OLLAMA_URL`          | —                         | Адрес локального Ollama. Не задан — `provider: "ollama"` в запросе отклоняется |
| `AGENTD_CLIENT_TOKENS`       | пусто                     | Клиентские токены через запятую. Пусто — аутентификация выключена |
| `AGENTD_REQUEST_TIMEOUT_SECS`| `60`                      | Таймаут запроса к провайдеру |
| `AGENTD_MAX_BODY_BYTES`      | `262144`                  | Предельный размер тела запроса |
| `AGENTD_MAX_CONCURRENCY`     | `16`                      | Предел одновременно обрабатываемых запросов |
| `AGENTD_LOG_FORMAT`          | `json`                    | Формат журнала: `json` или `text` |
| `AGENTD_LOG_TARGET`          | `stdout`                  | Куда писать журнал: `stdout` или `stderr` |
| `AGENTD_LOG_CONTENT`         | `false`                   | Писать ли в журнал тексты промптов и ответов |

> **Предупреждение.** Пустой `AGENTD_CLIENT_TOKENS` означает, что сервис
> обслуживает любого, кто до него дотянулся: проверка токена выключена.
> Сервис говорит об этом отдельной записью `WARN` при старте. В открытую
> сеть такой сервис выставлять нельзя.

Ключ провайдера в журнале появляется только маскированным
(`secr***alue`), целиком он не пишется никогда.

## Запуск

```bash
AGENTD_UPSTREAM_API_KEY=sk-... \
AGENTD_MODEL=deepseek-chat \
PORT=8080 \
cargo run --release
```

Пример запроса:

```bash
curl -sS -X POST http://127.0.0.1:8080/v1/chat \
  -H 'content-type: application/json' \
  -d '{"prompt": "Привет!", "settings": {"temperature": 0.3}}'
```

Успешный ответ:

```json
{
  "request_id": "0f0f…",
  "content": "Привет! Чем помочь?",
  "reasoning": null,
  "model": "deepseek-chat",
  "usage": { "prompt_tokens": 11, "completion_tokens": 7, "total_tokens": 18, "reasoning_tokens": null },
  "timing": { "duration_ms": 812, "sent_at": 1788976567, "received_at": 1788976568 },
  "policy": { "input": [], "output": [], "judge": null }
}
```

При включённой аутентификации к запросу добавляется заголовок
`Authorization: Bearer <токен>`.

## Эндпоинты

| Метод и путь      | Назначение |
|-------------------|------------|
| `POST /v1/chat`   | Диалог с моделью. Ровно одно из полей `prompt` или `messages` |
| `GET /v1/models`  | Модели, разрешённые конфигурацией |
| `GET /healthz`    | Живость процесса, к провайдеру не обращается |
| `GET /readyz`     | Готовность: 200 при валидной конфигурации, 503 при невалидной |

Ошибки приходят единым конвертом:

```json
{ "error": { "code": "invalid_request", "message": "…", "request_id": "…" } }
```

| Код | Когда |
|-----|-------|
| 400 | Невалидный запрос: оба или ни одного из `prompt`/`messages`, поле `api_key`, модель вне белого списка, `ollama` без настроенного адреса |
| 401 | Нет клиентского токена или он неизвестен |
| 413 | Тело больше `AGENTD_MAX_BODY_BYTES` |
| 422 | Запрос отклонён политикой конвейера |
| 429 | Превышена конкурентность либо провайдер ограничил частоту |
| 502 | Провайдер вернул ошибку |
| 504 | Провайдер не ответил в отведённое время |

Идентификатор запроса возвращается в заголовке `x-request-id` и в теле —
и в успешном ответе, и в ошибке.

## Контейнер

```bash
docker build -t agentd .
docker run --rm -p 8080:8080 -e AGENTD_UPSTREAM_API_KEY=sk-... agentd
```

Образ многостадийный: рантайм на `debian:bookworm-slim` без инструментов
сборки, порт берётся из `PORT`, `HEALTHCHECK` опрашивает `/healthz`.

## Разработка против неопубликованного ядра

Образ и CI собираются из `main` репозитория `agent-cli`. Чтобы работать
против локальной копии ядра, положите рядом `.cargo/config.toml`
(он в `.gitignore`):

```toml
[patch."https://github.com/Egor-Liadsky/agent-cli"]
agentcore = { path = "../agent-cli/crates/core" }
agentupstream = { path = "../agent-cli/crates/upstream" }
```

Подменять нужно оба крейта: они лежат в одном репозитории, и половинчатый
`[patch]` собрал бы сервис из разных версий ядра.

Порядок обновления зависимостей `agentcore` и `agentupstream`:

1. Изменить ядро в `agent-cli`, прогнать там `cargo test`.
2. Запушить `agent-cli/main` — образ собирается именно из этой ветки.
3. В `agent-sever` временно убрать `[patch]` и выполнить
   `cargo generate-lockfile`, чтобы `Cargo.lock` зафиксировал новый коммит.
4. Прогнать `cargo test --locked` без `[patch]`: так расхождение ядра
   и сервиса обнаруживается до сборки образа.

Локальная сборка под `[patch]` переписывает записи `agentcore` и
`agentupstream` в
`Cargo.lock` на путь к соседнему каталогу. Образ собирается с `--locked`,
поэтому перед коммитом лок-файл нужно перегенерировать без `[patch]` —
шаг 3 выше. Проверить, что в лок-файле именно коммит, а не путь (и что у
обоих крейтов он один и тот же):

```bash
grep -A2 'name = "agentcore"' Cargo.lock
grep -A2 'name = "agentupstream"' Cargo.lock
```
