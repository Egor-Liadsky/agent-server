## Purpose

Ограничивает размер истории, отправляемой в вызов модели, операторским
лимитом контекстного окна по умолчанию, который клиент может только сузить
для одного запроса, и отклоняет запрос до обращения к провайдеру, если
оценка размера истории этот эффективный лимит превышает.

## ADDED Requirements

### Requirement: Операторский лимит контекстного окна по умолчанию
Сервис SHALL читать необязательную переменную окружения
`AGENTD_MAX_CONTEXT_TOKENS` при старте. Заданное значение MUST быть целым
положительным числом токенов; при иначе оформленном значении старт SHALL
завершаться фатальной ошибкой, как для прочих переменных `AGENTD_*` с
числовым значением. Не заданная переменная SHALL означать отсутствие
лимита: проверка размера истории не выполняется, поведение сервиса не
меняется.

#### Scenario: Лимит не задан
- **WHEN** `AGENTD_MAX_CONTEXT_TOKENS` не задана и клиент не передал
  `settings.max_context_tokens`
- **THEN** сервис отправляет историю модели без проверки её размера

#### Scenario: Некорректное значение лимита при старте
- **WHEN** `AGENTD_MAX_CONTEXT_TOKENS` задана значением, не являющимся
  положительным целым числом
- **THEN** сервис завершается фатальной ошибкой при старте и не начинает
  принимать запросы

### Requirement: Клиентское сужение лимита на один запрос
`POST /v1/chat` SHALL принимать в `settings` необязательное поле
`max_context_tokens` — целое положительное число токенов, действующее
только на этот запрос. Заданное клиентом значение, превышающее
операторский лимит по умолчанию (или заданное при отсутствующем
операторском лимите), SHALL быть отклонено ответом `400` с кодом ошибки
`context_limit_invalid`, а вызов модели SHALL не выполняться. Отсутствие
поля SHALL означать действие операторского лимита по умолчанию без
изменений. Поле `max_context_tokens`, как и остальные поля `settings`,
переданные на один запрос, SHALL не сохраняться в хранилище чата.

#### Scenario: Клиент сужает лимит
- **WHEN** операторский лимит по умолчанию задан значением N и клиент
  передаёт `settings.max_context_tokens`, меньшее либо равное N
- **THEN** сервис использует переданное клиентом значение как эффективный
  лимит для этого запроса

#### Scenario: Клиент пытается увеличить лимит
- **WHEN** операторский лимит по умолчанию задан значением N и клиент
  передаёт `settings.max_context_tokens`, большее N, либо операторский
  лимит не задан, а клиент передаёт `settings.max_context_tokens`
- **THEN** сервис отклоняет запрос `400` с кодом `context_limit_invalid` и
  не обращается к провайдеру

### Requirement: Отказ при превышении эффективного лимита
Перед вызовом конвейера обработки сервис SHALL оценить размер истории,
которая будет передана модели (объединение уже сохранённых сообщений чата,
если запрос ссылается на `chat_id`, и присланных клиентом `prompt` или
`messages`), в токенах. Оценка размера MAY быть приближённой при
отсутствии точного токенизатора провайдера, но SHALL быть документирована
как оценка. Если оценка превышает эффективный лимит (клиентский, если
задан и допустим, иначе операторский лимит по умолчанию), сервис SHALL
отклонить запрос ответом `400` с кодом ошибки `context_limit_exceeded` и
SHALL не обращаться к провайдеру. Запрос, для которого эффективный лимит
не определён (лимит по умолчанию не задан и клиент не передал своё
значение), SHALL не подчиняться этой проверке.

#### Scenario: История превышает эффективный лимит
- **WHEN** оценка размера истории и нового сообщения в токенах превышает
  эффективный лимит запроса
- **THEN** сервис отвечает `400` с кодом `context_limit_exceeded`, не
  вызывая провайдера, и запрос с `chat_id` не дописывает историю чата

#### Scenario: История укладывается в эффективный лимит
- **WHEN** оценка размера истории и нового сообщения в токенах не
  превышает эффективный лимит запроса
- **THEN** сервис вызывает провайдера как обычно
