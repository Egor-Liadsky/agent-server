## Why

Автомат состояния задачи (`src/task.rs`) сейчас знает только этапы
`planning → execution → validation → done` (с возвратом
`validation → execution` и `execution → planning`). После того как
трекер собрал план на этапе `planning`, следующий переход — сразу в
`execution`: явного места для вопросов пользователю о собранном плане
нет. Пользователь вынужден сам, неявно, в чате уточнять план и решать,
когда он готов к выполнению — автомат этого не отражает и не
подсказывает ни трекеру, ни клиенту (TUI), что сейчас идёт анкетирование,
а не исполнение.

## What Changes

- Добавить в конечный автомат новый этап `clarification` между
  `planning` и `execution`: `planning → clarification`,
  `clarification → execution` (после подтверждения готовности
  пользователем), `clarification → planning` (план требует пересборки
  по итогам вопросов).
- Автотрекер (промпт, предлагающий переход) обучается предлагать
  переход в `clarification`, когда план собран, но остаются открытые
  вопросы к пользователю, и переход в `execution` — только когда
  пользователь явно подтвердил готовность.
- Раздел системного сообщения "Состояние задачи:" и бриф возобновления
  паузы получают формулировки для этапа `clarification` (по аналогии с
  уже существующими для `planning`/`execution`/`validation`/`done`).
- Существующий цикл проверки и исправления
  (`validation → execution → validation → ... → done`) не меняется.

## Capabilities

### New Capabilities
- `task-state`: конечный автомат состояния задачи чата — этапы, допустимые
  переходы, автотрекер, раздел системного сообщения и бриф возобновления
  (фиксирует текущее поведение и добавляет этап `clarification`; спека
  для этой возможности в OpenSpec ранее не заводилась, хотя реализация
  уже есть в `src/task.rs`).

### Modified Capabilities
(нет — спеки для `task-state` в `openspec/specs/` ещё не существует)

## Impact

- `src/task.rs`: новый вариант `TaskStage::Clarification`, новые рёбра
  `EDGES`, обновление `parse`/`as_str`, промпта автотрекера, текста
  раздела состояния задачи и брифа возобновления.
- `src/store.rs`, `src/dto.rs`, `src/context.rs`, `src/app.rs`: там, где
  этапы задачи перечисляются явно (валидация входа, сериализация DTO,
  сборка контекста) — добавить новый этап.
- `src/tests.rs`, тесты в `task.rs`: покрыть новые рёбра автомата и
  отказ от недопустимых переходов (например, `planning → execution`
  напрямую, минуя `clarification`, если так решит design.md).
- `agent-cli` (клиент и TUI): экран состояния задачи и клиент
  (`crates/client/src/chats.rs`, `crates/cli/src/tui.rs`) отображают
  список этапов — обновление на стороне `agent-cli` понадобится отдельным
  изменением после того, как `agentcore`/протокол `agentd` зафиксирует
  новый этап (см. `CLAUDE.md`: правка ядра сначала в `agent-cli`, сюда —
  после пуша в `main`; здесь же меняется только сервис `agentd`, не
  ядро).
